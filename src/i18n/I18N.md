# Internationalization (i18n) Guide

## Overview

ChainSettle uses `next-intl` for internationalization. The frontend is built with English as the primary language, but the i18n infrastructure supports additional locales.

## Location

```
src/i18n/
  ├── config.ts           ← Locale configuration
  └── messages/
      └── en.json         ← English translations
```

## Configuration

### src/i18n/config.ts

```typescript
import { LocalePrefix } from 'next-intl/routing';

export type Locale = (typeof locales)[number];

export const locales = ['en'] as const;

export const defaultLocale: Locale = 'en';

export const pathnames = {
  // Define localized route mappings (optional)
};

export const localePrefix: LocalePrefix = 'as-needed';
```

**Configuration Details:**

| Setting | Value | Meaning |
|---------|-------|---------|
| `locales` | `['en']` | Supported locale codes |
| `defaultLocale` | `'en'` | Default locale when user's preferred locale isn't available |
| `localePrefix` | `'as-needed'` | Only add locale prefix to URL when needed (non-default locales) |

### isLocale Type Guard

```typescript
export function isLocale(value: string | undefined | null): value is Locale {
  return locales.includes(value as any);
}
```

**Usage:**
```typescript
if (isLocale(userPreference)) {
  // Safe to use as Locale type
  applyLocale(userPreference);
}
```

## Using Translations in Components

### Client Components

```typescript
'use client';

import { useTranslations } from 'next-intl';

export function LoginPage() {
  const t = useTranslations();

  return (
    <button>
      {t('auth.login_button')} {/* "Sign In with Stellar" */}
    </button>
  );
}
```

### Server Components

```typescript
import { getTranslations } from 'next-intl/server';

export async function Metadata() {
  const t = await getTranslations();

  return {
    title: t('app_title'),
    description: t('app_description'),
  };
}
```

## Adding a New Locale

### Step 1: Create Message File

Copy `en.json` to a new locale file:

```bash
cp src/i18n/messages/en.json src/i18n/messages/fr.json
```

Translate all values in `src/i18n/messages/fr.json`:

```json
{
  "auth": {
    "login_button": "Se connecter avec Stellar",
    "logout_button": "Se déconnecter"
  },
  "shipments": {
    "title": "Expéditions",
    "empty_state": "Aucune expédition pour le moment"
  }
}
```

### Step 2: Update Configuration

Add locale to `config.ts`:

```typescript
export const locales = ['en', 'fr'] as const;
```

### Step 3: Update Providers

Load the new message file in `src/app/providers.tsx`:

```typescript
import enMessages from '@/i18n/messages/en.json';
import frMessages from '@/i18n/messages/fr.json';

const messages = {
  en: enMessages,
  fr: frMessages,
};

export function Providers({ children, locale }: ProvidersProps) {
  return (
    <NextIntlClientProvider locale={locale} messages={messages[locale]}>
      {children}
    </NextIntlClientProvider>
  );
}
```

## URL Structure

### With Locale Prefix

When using `localePrefix: 'as-needed'`:

- English (default): `/shipments`
- French: `/fr/shipments`
- German: `/de/shipments`

No locale prefix is added for the default locale (`en`), keeping URLs clean.

### Linking Between Locales

```typescript
import { useRouter } from 'next-intl/client';

function LocaleSwitcher() {
  const router = useRouter();

  return (
    <>
      <button onClick={() => router.push('/', { locale: 'en' })}>
        English
      </button>
      <button onClick={() => router.push('/', { locale: 'fr' })}>
        Français
      </button>
    </>
  );
}
```

## Translation Keys

### Key Naming Convention

Use hierarchical keys for organization:

```json
{
  "auth": {
    "login": {
      "button": "Sign In",
      "error": "Login failed"
    }
  },
  "shipments": {
    "list": {
      "title": "Shipments",
      "empty": "No shipments"
    },
    "detail": {
      "title": "Shipment Details",
      "back": "Back to list"
    }
  }
}
```

**Usage:**
```typescript
t('shipments.list.title')     // "Shipments"
t('shipments.detail.title')   // "Shipment Details"
t('auth.login.button')        // "Sign In"
```

### Key Naming Patterns

| Pattern | Example | Use Case |
|---------|---------|----------|
| `.button` | `auth.login.button` | Interactive elements |
| `.title` | `shipments.title` | Page/section headings |
| `.label` | `form.email.label` | Form input labels |
| `.error` | `validation.required.error` | Error messages |
| `.help` | `form.amount.help` | Helper text/tips |
| `.empty` | `shipments.empty` | Empty state messages |

## Pluralization

### Using `useTranslations` with Plurals

```typescript
const t = useTranslations();

const shipmentCount = 5;
const message = t('shipments.count', { count: shipmentCount });
// Message file: "shipments.count": "You have {count} shipments"
// Result: "You have 5 shipments"
```

### Message File with Plurals

```json
{
  "shipments": {
    "count": "{count, plural, =0 {No shipments} one {# shipment} other {# shipments}}"
  }
}
```

## Number and Date Formatting

### Using `useFormatter`

```typescript
import { useFormatter } from 'next-intl';

export function TransactionAmount({ amount }: { amount: string }) {
  const format = useFormatter();

  return (
    <div>
      {/* 1234.56 → "1,234.56" (en) or "1.234,56" (de) */}
      {format.number(parseFloat(amount), { style: 'decimal', maximumFractionDigits: 2 })}
    </div>
  );
}
```

### Localized Dates

```typescript
import { useFormatter } from 'next-intl';

export function TransactionDate({ date }: { date: string }) {
  const format = useFormatter();

  return (
    <div>
      {/* 2026-09-27 → "September 27, 2026" (en) or "27. September 2026" (de) */}
      {format.dateTime(new Date(date), {
        year: 'numeric',
        month: 'long',
        day: 'numeric',
      })}
    </div>
  );
}
```

## Best Practices

1. **Keep keys lowercase and use underscores**: `auth.login_button`, not `auth.LoginButton`

2. **Group related messages**: All shipment-related translations under `shipments.*`

3. **Use complete sentences**: Avoid fragments that don't translate well
   - ✅ "Sign in with your Stellar wallet"
   - ❌ "Sign in"

4. **Don't hardcode dynamic content**:
   - ✅ "Shipment {id} created" (use template variable)
   - ❌ "Shipment 123 created" (hardcoded value)

5. **Check for missing translations**:
   - Add all keys from `en.json` to new locale files
   - Use type-safe key access with TypeScript

6. **Keep file size reasonable**:
   - If `en.json` exceeds 10KB, consider splitting by feature:
     - `auth.json`, `shipments.json`, `errors.json`

7. **Document context for translators**:
   - Add comments for ambiguous or technical terms
   - Example: `"status.pending": "// Payment pending from buyer"`

## Troubleshooting

### "Missing key: ..."

**Cause:** Key referenced in code doesn't exist in message file.

**Solution:**
1. Add key to `en.json`
2. Add same key to all locale files
3. Restart dev server

### Translation not updating

**Cause:** Next.js cache or stale build.

**Solution:**
1. Delete `.next/` directory
2. Restart dev server
3. Hard refresh browser

### Locale not switching

**Cause:** Browser cache or incorrect locale code.

**Solution:**
1. Clear browser cache
2. Verify locale code exists in `config.ts`
3. Check URL structure matches `localePrefix` setting
